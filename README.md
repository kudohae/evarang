# 에바랑 — OPIc 모의고사

실제 OPIc 진행 순서(Background Survey → Self Assessment → Pre-Test Setup → Sample Question → 본 시험 → 난이도 재조정)를 그대로 따르는 모의고사입니다. 답변은 AssemblyAI로 군말까지 받아쓰고, 무료 등급 모델이 ACTFL 기준으로 등급과 문항별 첨삭을 만듭니다. 발음은 평가하지 않습니다.

## Vercel 배포

1. [vercel.com](https://vercel.com)에 GitHub 계정으로 가입합니다.
2. **Add New → Project**에서 `kudohae/evarang` 저장소를 Import 합니다.
3. **Environment Variables**에 아래 값을 넣습니다. 키가 없는 모델은 평가 순서에서 건너뜁니다.

   | 이름 | 필수 | 설명 |
   |---|---|---|
   | `ACCESS_CODE` | 예 | 사이트 접근 코드. 비워두면 주소를 아는 누구나 내 API 키로 비용을 쓸 수 있습니다. |
   | `ASSEMBLYAI_API_KEY` | 예 | 음성인식 |
   | `GEMINI_API_KEY` | 예 | 평가(무료 등급), 그리고 AssemblyAI가 안 될 때의 보조 음성인식 |
   | `GROQ_API_KEY` | 권장 | Gemini 무료 한도를 다 쓴 날의 평가 (GPT-OSS 120B, 무료 등급) |
   | `DATABASE_URL` | 수집 시 | Neon Postgres 연결 문자열. Vercel Storage에서 Neon을 연결하면 자동으로 들어갑니다(`POSTGRES_URL`도 인식). |
   | `BLOB_STORE_ID` 또는 `BLOB_READ_WRITE_TOKEN` | 수집 시 | Blob 스토어를 프로젝트에 연결하면 둘 중 하나가 자동으로 들어갑니다. 요즘 연결 방식은 `BLOB_STORE_ID`만 넣고 인증은 Vercel이 OIDC로 처리합니다. 스토어는 Private 접근이어야 합니다. |
   | `ADMIN_CODE` | 수집 시 | `/admin` 관리자 화면 코드. 접근 코드와 다르게, 길게 정하세요. 비워두면 관리자 화면이 닫힙니다. |
   | `CRON_SECRET` | 권장 | 매일 03:00(KST) 만료 기록 삭제 작업의 인증값. 넣어두면 Vercel Cron만 그 작업을 부를 수 있습니다. |
   | `PRIVACY_OPERATOR` | 수집 시 | 개인정보 처리방침에 표시할 운영자 이름 |
   | `PRIVACY_CONTACT` | 수집 시 | 개인정보 문의 연락처(이메일) |

4. **Deploy**를 누릅니다. 이후 연결된 브랜치에 push할 때마다 자동으로 다시 배포됩니다.

Vercel의 Production 브랜치는 기본적으로 `main`입니다. 이 작업 브랜치를 `main`에 합치거나, 프로젝트 Settings → Git에서 Production Branch를 바꾸세요.

> Vercel Hobby(무료) 플랜은 비상업적 용도만 허용합니다. 유료화할 때는 Pro 플랜으로 바꿔야 합니다.

## 로컬 실행

```bash
npm install
cp .env.example .env.local   # 키 입력
npm run dev                  # http://localhost:3000
```

마이크 녹음은 HTTPS 또는 localhost에서만 동작합니다.

## 구조

```
src/
  app/                    페이지와 API 라우트
    api/transcribe        녹음 → AssemblyAI (Universal-3.5 Pro, disfluencies: true)
    api/evaluate/*        문항별 첨삭(5문항씩 묶음), 종합 판정
    api/access            접근 코드 확인 → httpOnly 쿠키
    api/auth, api/account 가입·로그인·로그아웃, 회원정보 수정·탈퇴 (lib/server/auth.ts)
    api/me                계정에 저장한 시험 기록과 녹음 (lib/server/user-exams.ts)
    api/records           동의한 시험의 저장·녹음 업로드·삭제
    api/admin/*           관리자 화면용 목록, 기록, 녹음
    api/cron/purge        보유 기간이 지난 기록 삭제 (vercel.json)
    privacy               개인정보 처리방침
  components/exam/        시험 화면 (설문, 자가평가, 장비 점검, 문항, 재조정)
  components/report/      평가 보고서
  lib/content/            설문 항목, 자가평가 단계, 문항 은행 (설문 주제 63개, 돌발 주제 15개)
  lib/exam/compose.ts     출제 규칙
  lib/evaluation/         평가 기준 프롬프트와 응답 스키마
  lib/server/llm.ts       모델 공급자별 호출 (Gemini, Groq)과 한도 판단
  lib/models.ts           평가 모델 순서
```

녹음과 결과는 사용자의 브라우저(IndexedDB)에 저장됩니다. 서버에는 "예측 개선을 위한 저장"에 동의한 시험만 남습니다.

## 회원

- **가입·로그인:** 이메일과 비밀번호. `DATABASE_URL`만 있으면 켜집니다(Blob은 필요 없음). 화면은 `/signup`, `/login`, `/account`(닉네임·이메일·비밀번호 변경, 로그아웃, 탈퇴).
- **저장:** Postgres의 `users`, `sessions`, `auth_attempts` 표(처음 요청 때 자동 생성). 비밀번호는 scrypt 해시로만, 세션은 쿠키 값의 SHA-256만 저장합니다. 세션은 30일, 비밀번호를 바꾸면 다른 기기의 세션은 모두 끊깁니다.
- **막아둔 것:** 다른 사이트에서 보낸 요청(Origin 검사), 이메일당 15분에 로그인 10회·IP당 50회, IP당 1시간에 가입 10회.
- **계정에 시험 기록 저장:** 로그인한 회원이 한 번 동의하면(홈 화면 안내 또는 내 정보 → 시험 기록 저장), 기록을 `user_docs` 표(종류 `exam`·`session`·`note`·`story`)에, 녹음을 비공개 Blob `users/{회원}/{종류}/{기록}/{번호}`에 저장합니다. 첫 버전의 `user_exams` 표는 처음 요청 때 `user_docs`로 옮기고(여러 번 돌아도 안전), 그 녹음은 옛 경로 `users/{회원}/exams/{기록}/{문항}`을 그대로 씁니다. 그때 이 브라우저에 있던 기록도 함께 올립니다. 이후에는 보고서가 바뀔 때마다(평가, 실제 등급, 다시 받아쓰기) 다시 보냅니다. 브라우저가 작업본이고 계정은 그 사본입니다.
- **다른 기기:** 홈의 "지난 시험"에 계정의 기록이 함께 나오고, 보고서를 열면 계정에서 불러와 이 브라우저에 사본을 둡니다. 녹음은 재생할 때 계정에서 받아옵니다.
- **삭제:** 저장을 끄면 계정의 기록과 녹음을 모두 지웁니다. 탈퇴하면 계정과 함께 지웁니다. 브라우저의 기록과 예측 개선용 기록은 따로입니다.
- **아직 없는 것:** 비밀번호 찾기(메일 발송 필요), 이메일 인증, 소셜 로그인, 휴대폰·본인 인증, 기록 하나만 골라 계정에서 지우는 화면(API는 있음).
- **충돌:** 기록마다 `updatedAt`이 있고, 계정에 더 최근 사본이 있으면 저장 요청은 409와 그 사본을 받습니다. 브라우저는 그 사본으로 바꿉니다. 지운 기록은 계정에 삭제 표시로 남아 다른 기기도 지웁니다.
- **로컬 개발:** 로컬 Postgres를 쓰려면 Neon HTTP 프로토콜을 흉내 내는 프록시를 띄웁니다.

  ```bash
  npm i --no-save pg
  node scripts/neon-http-proxy.mjs 4444 postgres://postgres@127.0.0.1:5432/postgres
  DATABASE_URL=postgres://postgres:x@localhost/postgres NEON_FETCH_ENDPOINT=http://localhost:4444/sql npm run dev
  ```

## 동의와 데이터 수집

- **동의 화면:** 시험 안내 다음, Background Survey 전에 나옵니다. 해외 전송(AssemblyAI·Google·Groq)과 만 14세 이상은 필수, 예측 개선용 저장은 선택입니다. 저장소(`DATABASE_URL`, `BLOB_STORE_ID` 또는 `BLOB_READ_WRITE_TOKEN`)가 설정되지 않았으면 선택 항목은 보이지 않습니다. 전문은 `/privacy`.
- **저장하는 것:** 설문 답변, 자가평가, 문항, 받아쓴 글과 지표, 평가 결과, 대기 화면에서 고른 실제 OPIc 등급(Postgres `exam_records` 표), 답변 녹음(Blob `exams/{기록번호}/{문항}.webm`, 비공개).
- **언제:** 보고서 화면이 열려 있을 때 내용이 바뀔 때마다 다시 보냅니다(평가 완료, 실제 등급 입력, 재평가). 실패하면 보고서 아래에 이유가 나오고 다음 변경 때 다시 시도합니다.
- **삭제:** 사용자는 보고서 아래 "저장된 데이터 삭제"로 지웁니다. 브라우저에만 있는 비밀값으로 본인을 확인하므로, 브라우저 데이터를 지우면 그 기록은 직접 지울 수 없게 됩니다(그때는 문의 연락처로 기록 번호를 받아 관리자가 지웁니다). 보유 기간 2년이 지나면 매일 03:00 작업과 관리자 화면을 열 때 자동으로 지워집니다.
- **관리자 화면:** `/admin`에서 `ADMIN_CODE`로 들어갑니다. 기록 목록, 예상 등급과 실제 등급의 일치율(정확히 일치, 한 단계 이내, 평균 차이), 기록별 보고서와 녹음 재생, 삭제가 있습니다.
- **확인하지 못한 것:** 개발 환경에서 Neon과 Blob에 접속할 수 없어 실제 저장은 시험해보지 못했습니다. SQL은 PGlite로 검증했습니다. 배포한 뒤 동의하고 시험을 한 번 본 다음 `/admin`에 기록과 녹음이 보이는지 확인하세요.

## 평가 모델

사용자는 모델을 고르지 않습니다. 무료 등급 모델을 좋은 것부터 차례로 씁니다.

Gemini 3.8 Flash → 3.7 Flash → 3.6 Flash → 3.5 Flash → 3.5 Flash-Lite → GPT-OSS 120B (Groq)

- **분당 한도(429)나 서버 혼잡(503):** 그 시험의 결과를 아직 하나도 받지 않았으면 바로 다음 모델로 넘깁니다. 모델마다 분당 한도가 따로라서, 동시에 끝난 시험들이 여러 모델로 나뉘어 평가됩니다(분당 합계 약 35번, 동시에 평가 약 10명). 이미 결과를 일부 받았으면 공급자가 알려준 시간만큼 기다렸다가 같은 모델로 다시 보냅니다(최대 4번). 모든 모델이 분당 한도에 걸려 있으면 가장 좋은 모델에서 기다립니다.
- **하루 한도:** 다음 모델로 내려갑니다. 그때까지 받은 결과는 버리고 다음 모델로 처음부터 평가합니다. 보고서 하나를 두 모델이 나눠 채점하지 않게 하려는 것입니다.
- **요청 수:** 시험 한 번에 3번(첨삭 2번, 종합 1번), 동시에 2개까지 보냅니다. Flash 모델은 무료 등급에서 분당 5번, 하루 20번이라 모델 하나로 하루 6번쯤 평가할 수 있습니다. Flash-Lite는 하루 500번입니다(2026년 10월 AI Studio 기준).
- **한도 초기화:** Gemini의 하루 한도는 태평양 시간 자정, 한국 시간 오후 4시(11월~3월은 오후 5시)에 다시 채워집니다.
- **보조 음성인식:** 시험 한 번에 16번쯤 요청하므로 Flash-Lite부터 씁니다. Flash 모델의 하루 한도는 평가에 남겨둡니다.
- 모델마다 등급을 매기는 경향이 다를 수 있습니다. 어느 모델이 채점했는지 기록에 남으므로, 관리자 화면에서 모델별로 실제 등급과 비교할 수 있습니다.

## 음성인식이 안 될 때

- **시험 전 확인:** Pre-Test Setup의 녹음 테스트를 실제로 받아씁니다. 받아쓰기가 동작하지 않으면 시험을 시작할 수 없습니다.
- **보조 음성인식:** AssemblyAI가 실패하면 서버가 Gemini로 받아씁니다. 오류 문구로 크레딧 소진을 판단하면, 10분 동안은 AssemblyAI를 건너뜁니다.
  - Gemini는 단어별 시간을 주지 않습니다. 그래서 브라우저가 녹음의 소리 크기로 멈춤 위치와 말하기 속도를 추정하고, 보고서에 추정치라고 표시합니다.
  - 전환되었다는 안내는 한 번만 띄웁니다. 시험 전 확인 단계에서 띄우거나, 시험 도중에 전환되었다면 시험이 끝난 뒤에 띄웁니다. 문항을 푸는 중에는 띄우지 않습니다.
- **다시 받아쓰기:** 받아쓰지 못한 답변은 평가에서 빠집니다. 녹음이 브라우저에 남아 있으므로 평가 화면이나 보고서에서 다시 받아쓸 수 있고, 보고서에서 다시 받아쓰면 그 답변까지 넣어 다시 평가합니다.
- **크레딧 소진 판단의 한계:** AssemblyAI가 크레딧 소진 때 실제로 보내는 오류 문구는 확인하지 못했습니다. `balance`, `credit`, `insufficient` 같은 단어로 판단하므로(`src/app/api/transcribe/route.ts`), 실제 문구가 다르면 "연결되지 않아"라는 안내가 대신 나갑니다. 이 경우에도 보조 음성인식으로 바뀌는 동작은 같습니다.

## 출제 규칙의 근거

공식 사이트에서 확인한 것: 진행 순서, 질문 청취 2회(처음 + 다시 듣기 1회), 문항별 답변 시간 제한 없음, 12~15문항, 시험 40분, 7번 뒤 난이도 재조정.

수험생 자료가 대체로 일치하는 것: 난이도 1~2는 12문항·3~6은 15문항, Q1 자기소개 채점 제외, Q2~10 콤보, Q11~13 롤플레이, Q14~15 어드밴스(5~6단계).

자료마다 엇갈려 다수 의견을 따른 것: 다시 듣기는 질문이 끝난 뒤 5초 안에만 가능, 질문이 끝나면 바로 녹음 시작, 3~4단계의 Q14~15는 비교 + 질문하기.

규칙은 `src/lib/exam/compose.ts`와 `src/lib/capture/policy.ts`(`EXAM_POLICY`: 다시 듣기 5초 안에 1번, 질문 글자 숨김, 다시 말하기 없음)에 모여 있습니다.

## 한계

- 예상 등급은 공식 결과가 아닙니다.
- 질문 음성은 브라우저 내장 TTS라 실제 시험의 Ava 목소리와 다릅니다. Edge나 macOS Safari의 자연스러운 음성이 가장 낫습니다.
- 음성인식이 확신하지 못한 단어는 보고서에 따로 표시하지만, 이는 발음 평가가 아닙니다.
- Self Assessment·Survey 문구는 실제 시험을 본뜬 것입니다. 유료 서비스로 공개하기 전에 문구와 서비스 이름(OPIc은 ACTFL의 상표)을 검토해야 합니다.
